# Turismo — plano de implementação

> **Para agentes:** use superpowers:subagent-driven-development. Passos com checkbox.

**Meta:** seção de Turismo (rotas, dormir, comer, o que fazer, distritos) e Chapada dentro da Grande Cuiabá.
**Arquitetura:** conteúdo em arquivo (coleções do core); blocos de UI no `kizuna-core`; páginas do starter só montam.
**Stack:** Next 16, React 19, Tailwind 4, vitest, `@kizuna/core/server/content`.
**Spec:** `docs/superpowers/specs/2026-10-28-turismo-design.md`

## Restrições globais
- Sem política. Só `status: aprovado` vai ao ar; fraco fica `rascunho`/`revisao`.
- Classe Tailwind inválida em .md/plano quebra o CSS (Tailwind varre .md): não escrever nomes de classe nesses arquivos.
- Não commitar sem o usuário pedir (core + starter juntos, só sob comando).
- Fotos só de licença livre, créditos no campo `creditos`.

## Foco de revisão
- Entrada antiga de `lugares` (sem `tipo`) continua válida e visível.
- Roteiro cuja parada aponta para lugar inexistente ou não aprovado: parada some, página não quebra.
- Roteiro `rascunho` não aparece em listagem, sitemap nem por URL.
- Cidade sem conteúdo de turismo: seção mostra estado vazio, sem erro.
- Filtro por cidade inclui a praça (Cuiabá, VG, Chapada).
